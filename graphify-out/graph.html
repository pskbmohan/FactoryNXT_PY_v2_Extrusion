### Session Memory: FactoryNXT_PY_v2_Extrusion

Repo role: Production MES (Manufacturing Execution System) for aluminum extrusion plants.
Python (NOT TypeScript). Reference source — we extract patterns (domain modeling, Flask app
factory, APS scheduling, state machines, seed-data ergonomics), not copy code verbatim.

Tech stack:
- Python 3.10+ / Flask 3.0 / Flask-SQLAlchemy 3.1 / Flask-Migrate 4.0 / PostgreSQL 15
- Jinja2 + Tailwind CSS (CDN) — server-rendered, no SPA framework
- Docker + docker-compose + Alembic migrations
- 6 services under app/services/: aps_engine, erp_adapter, plc_adapter, scheduler, kpi_engine, process_simulator

Model layout (105 classes across 3 files):
- app/models.py       — 94 classes / 1724 lines. HIGHEST blast radius.
- app/models_aps.py   — 6 classes  / 188 lines.  APS versioning.
- app/models_routing.py — 5 classes / 175 lines. V2 visual routing.
- Coexistence note: RoutingStep (legacy) and RoutingStepV2 (V2 builder) both exist;
  operation-execution engine reads the legacy one.

Read first:
1. README.md first 100 lines — domain overview.
2. app/models.py first 200 lines — establishes pattern (Line, Machine, Station, WorkOrder…).
3. app/__init__.py (full, 190 lines) — blueprint registration + auto-startup seed.
4. app/services/aps_engine.py first 150 lines — slot math, constants, imports.

Do NOT touch without understanding:
- app/__init__.py lines 119-188 (auto-seed at EVERY startup, silent on error, order matters).
- app/services/aps_engine.py internals (deterministic scheduler; run tests/test_aps_engine.py after any change).
- app/__init__.py blueprint registration order.
- scripts/seed_data.py top-level sequence.
- app/models.py — touched by every route, service, seed, test, migration.

API boundaries inconsistent: half the blueprints use url_prefix, half hardcode routes (non-blocking).

Routing (DRAFT→RELEASED→OBSOLETE), Alert (Open→Acknowledged→Closed),
IntegrationJob (Pending→Running→Success|Failed→RetryQueued).
